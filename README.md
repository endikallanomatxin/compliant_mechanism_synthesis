# Compliant Mechanism Synthesis

A local workbench for direct optimization of point-and-beam structures in **2D and 3D**. Nonlinear deformation paths are central: the search discovers the position and orientation traced by the mobile body as it moves along the least-stiff direction of the structure. There are no learned models.

```sh
uv sync --extra dev
uv run cms-view
```

Open **http://127.0.0.1:8000**. The synthesis view opens first. The Specification page starts from the default design. Edit node coordinates and roles, add/remove nodes, enable beams and set their radii, choose 2D/3D, and configure desired pose waypoints. The separate Configure synthesis dialog uses tabs for Population, Gradient, Mutations, Diversity, Cost and Analysis, with directly visible fields in each tab. It contains population size, mutation probabilities and scales, crossover, parent focus, gradient step sizes, hybrid cycles, diversity, pose weights, continuation settings and compute device. Apply parameters without restarting, or apply and restart from the currently applied specification; growing the population generates additional variants of retained designs. Device changes require a restart. Applying the specification preserves the current synthesis settings. Node coordinates use metres; trajectory translations and rotations are edited in mm and degrees. A live structure preview and enlarged trajectory detail show the local draft. Validate to create a new synthesis run; invalid specifications leave the previous run intact. The synthesis screen separates the main viewer, search controls, population and movement diagnostics. Open the Specification page to edit the retained draft. Switching pages or closing the synthesis settings dialog keeps pending edits without applying them. The WebGL2 viewer overlays real and target rigid bodies at matching progress (green solid / violet dashed), shows physical position and orientation errors, and includes a common-origin orientation comparison. Playback interpolates between computed states, using shortest-arc quaternion interpolation in 3D and reconstructing rigid attachments exactly; this does not add FEM equilibria. The viewer supports deformation playback, global and body reference frames, trajectories of the mobile center, attachments and axis tips, selectable displacement/rotation plots, visual displacement magnification, and orbiting the 3D camera. Export JSON to inspect all states and diagnostics. Magnification affects only rendering. The mobile body keeps its rigid shape and its true rotation; its translations are amplified. It automatically fits the maximum path displacement to the scene; the logarithmic slider supports ×1–×10,000, with the active factor shown beside it.

## Mechanics and deformation paths

All coordinates use metres, circular-section radii use metres, forces use newtons, and moments use N·m. PyTorch float64 kernels provide derivatives with respect to geometry, radii and beam presence. A unique undirected edge list defines the symmetric connectivity; presence weights stiffness and material independently of radius.

- Euler–Bernoulli beams include axial and bending stiffness, plus torsion in 3D. The linear solver provides an initial-stiffness reference and condensed rigid-body stiffness.
- Corotational beam energy admits large translations and rotations with small local strains. In 2D it uses chord-relative endpoint angles. In 3D it uses transported section directors and relative rotation vectors. Fixed nodes are clamped; mobile nodes follow an exact finite rigid-body transformation.
- Natural-motion continuation holds the mobile body at each computed pose and minimizes elastic energy over free-node degrees of freedom with Newton and line search. The relaxed tangent is the Schur complement `Kbb − Kbf Kff⁻¹ Kfb`. In 3D it includes the curvature of the local spatial rotation chart, not just a change of Jacobian.
- Incremental motion is a spatial twist. Its metric is `||translation||² + L² ||rotation||²`, using a configurable characteristic length `L` (default 50 mm), independent of objective weights. The lowest eigenvector of the scaled relaxed tangent determines the motion direction. Its sign maximizes alignment with the corresponding desired increment; continuity breaks ties. The desired path sets travelled arc length (Gauss quadrature of its physical twist speed), not the direction of motion.
- Explicit Euler integration recomputes free equilibrium and the soft mode at every increment and desired waypoint. The path is anchored at the undeformed rest waypoint; for an interior rest it traces independently towards both endpoints and displays the combined path in increasing progress. Refinement checks compare the current path with twice as many increments. This is quasi-static mode-flow integration, not free dynamics or a fixed external-force simulation.
- Each state records progress, node positions, mobile translation/rotation, elastic energy, generalized reaction needed to hold that pose, free-equilibrium residual, Newton iterations, effective stiffness spectrum and the soft spatial mode. The JSON output contains these values in physical units. In 3D generalized moments are work-conjugate to body rotation-vector coordinates.
- Equilibrium derivatives use the implicit function theorem at converged states. The residual derivative is retained while the free tangent inverse is detached. Gradients propagate through relaxed tangents, the isolated lowest eigenvector, and every integrated body pose. A custom spectral backward handles repeated higher eigenvalues without dividing their mutual gaps. Differentiability applies to smooth branches with an isolated lowest mode and a stable sign choice. Mode crossings, zero-alignment sign changes and topology changes are discrete decisions.

This formulation excludes contact, plasticity, shear deformation, distributed loads and dynamics. The natural path stops at failed free equilibrium, significant negative effective stiffness, or an ambiguous lowest mode (relative gap below the configured tolerance). It does not invent a unique motion at a bifurcation. A perpendicular target can leave the initial sign tied, making the path nondifferentiable under perturbations that change that tie. Rotation-vector coordinates require care near π. The separate load-controlled FEM functions remain available for analytical verification, but search and viewer use only natural-motion continuation. The viewer draws cubic Hermite beam curves with end tangents tied to nodal section rotations. All beam joints transfer moments; there are no rotational releases or hinges.

## Direct optimization

The initial example has 16 nodes: two clamped nodes, two rigidly tied mobile nodes and twelve free nodes arranged at four longitudinal stations. It starts with 37 beams and exposes 118 admissible connections to topology evolution. Both search methods vary free-node positions, bounded radius logits and continuous beam-presence logits. Anchors and mobile reference geometry remain fixed. A shared candidate edge pool contains all admissible node pairs except pairs internal to the fixed support or mobile body. Each individual has its own discrete topology mask; evolution can add or remove beams. Disconnected structures are rejected before FEM.

The objective matches the mobile pose to the specified trajectory at each path progress, integrated over the progress factors of all converged path states using trapezoidal quadrature. It also penalizes the squared ratio of lowest to next stiffness (multiple soft motions), a deficit in the next stiffness below a configurable floor in N/m (insufficient transverse support), material usage and close nodes. Increasing all stiffnesses does not improve the ratio; reducing all radii cannot satisfy the support floor.

The default target passes through six generalized poses: an S-shaped translation with 6 mm final lift, −2 mm final lateral travel and a nonmonotonic rotation ending at 0.12 rad. Cubic Hermite interpolation passes through every waypoint with continuous tangents. Edit factor/pose rows in the browser; progress factors must increase from 0 to 1. The rest progress is configurable and must have its own zero-pose waypoint. With rest at zero the path starts undeformed; with rest in the middle both halves start from that undeformed state and are combined for playback. There is no prescribed generalized load or preloading. Changing the desired trajectory changes both the direction-sign guidance and travelled arc length, so it invalidates the mechanical path cache. The viewer samples the target at 101 points and displays it alongside the actual equilibrium path.

A persistent population starts from one reference design plus seeded, independent mutations. The defaults retain 32 structures and evaluate up to 16 together; population and evaluation batch size are independent controls. Position and orientation errors are averaged within their groups, divided by independently configurable metre/radian scales, and combined using normalized nonnegative weights. Either group can be disabled with a zero weight, but both cannot be zero.

Gradient search replays the complete mode-flow from stored parent free equilibria, avoiding another Newton solve while retaining mode and accumulated path derivatives. It tries the configured step first and halves it only for parents whose proposals fail or worsen their score, accepting the first nonworsening proposal independently for each parent. The backtracking count is a maximum, not a fixed number of alternatives. The default automatic method is a hybrid cycle of three gradient steps followed by one evolutionary generation; both counts and relative geometry/radius/beam-weight step sizes are configurable. Manual gradient and evolution buttons remain available.

Evolution devotes roughly 80% of offspring to local variants of the leading 25% of parents ranked by physical quality and population crowding. Parent probabilities are proportional to inverse squared rank, so the best receives the most variants. These offspring use half-size mutations and half the topology-flip probability. The remaining offspring use tournament selection, crossover and full-size mutations to preserve exploration. The configurator exposes independent node/radius/beam-weight mutation probabilities, topology-flip probability, mutation intensity, geometry scale, local-search fractions, crossover, tournament size, gradient step and backtracking count. Zero probability disables the corresponding mutation operator. Mutation magnitude increases after stagnation.

Explicit elites survive each generation; selection fills the remaining slots from convergent offspring and parents using physical quality and a similarity penalty. Similarity compares corresponding free-node geometry, discrete connections, active beam radii and effective beam weights; these components, the similarity radius and the diversity weight are configurable. Radii of absent beams do not count. Survivor selection greedily penalizes similarity to already selected designs, while parent fitness adds mean similarity to the population. The best physical objective remains preserved. Setting diversity weight to zero restores selection by physical score alone. This comparison uses the shared node identities; it is not a graph-isomorphism test. Nonconvergent candidates are rejected independently.

`batching.py` uses `torch.func.vmap` for energy, residuals and element tangents and batched linear solves. `tangents.py` differentiates each beam in its 6 (2D) or 12 (3D) endpoint coordinates and assembles the global tangent through exact nodal kinematics, including the curvature of the rigid-body attachment transform. Evaluation is bounded by `--evaluation-batch-size` (default from the search config), so large populations and backtracking alternatives are split into tensor batches. Element Hessian rows are differentiated in blocks controlled by `--hessian-chunk-size`. Gradient graphs are differentiated and released per batch. These controls limit peak memory without shrinking the population.

Each individual has its own free-equilibrium line-search mask and convergence state; one failed structure does not abort the other designs. Newton compacts active designs before residual/tangent calculations and solves; line search evaluates only proposals still waiting for acceptance. Failed individuals are excluded from later mode and free-equilibrium evaluations. Discrete topology and connectivity checks happen outside the differentiable FEM.

Accepted deformation paths are stored as detached CPU coordinates and diagnostics, with only the retained population kept after selection. The viewer reconstructs positions, rotations, energy and reaction from these equilibria without resolving them. Viewer responses are cached until the design, target or analysis settings change; selecting any evaluated individual does not repeat equilibrium continuation. The canvas buffer is resized only when its dimensions change.

The browser lists retained individuals in score order with structure thumbnails, objective, percentage gap from the best, beam count and topology differences. Batch diagnostics show local and exploratory offspring counts. Select one to inspect its nonlinear path, and superpose the alternative geometries to compare the population. JSON includes the population and batch diagnostics. Cards show physical objective, mean similarity and normalized parent fitness separately. Configure it with `--gradient-steps-per-evolution`, `--evolution-steps-per-cycle`, `--position-weight`, `--orientation-weight`, `--diversity-weight`, `--population`, `--elites`, `--tournament-size`, `--crossover-probability` and `--topology-mutation-probability`. Population size and mechanics share one device.

TensorBoard logs best and median objective, objective distributions, accepted improvements, population diversity, batch size, converged/rejected candidates, batch time and path residual. The browser displays and exports the corresponding states.

The numerical diagnostics panel plots requested and accepted gradient rates (the last 100 gradient steps), reports acceptance at each backtracking rate and the mean candidate objective improvement before survival selection. These rates scale normalized geometry, radius and presence directions. Effective soft/next stiffness curves, free-node Newton iterations and residual-to-tolerance ratios describe the computed deformation states. An explicit refinement button solves only the selected structure with twice the continuation increments, without altering population, settings or cached search paths. It overlays both paths and reports maximum translation/orientation differences and integrated tracking-cost change, using linear interpolation on a shared progress grid. Small refinement differences are evidence of resolution for this path, rather than a guarantee of branch completeness. Gradient and refinement metrics are also logged to TensorBoard.

## Code layout

- `mechanics.py`, `elements.py`: design contract, material, linear assembly and rigid reduction.
- `nonlinear.py`: corotational energy, nonlinear configurations and load-controlled verification.
- `soft_modes.py`: relaxed spatial stiffness, device-local spectrum, implicit free equilibrium and natural compliant motion.
- `batching.py`: simultaneous equilibrium continuation with independent convergence masks.
- `optimization.py`: persistent population, crossover, topology mutations and batched gradient search.
- `resolution.py`: isolated continuation refinement and path comparison.
- `server.py`, `web/`: local JSON API and dependency-free HTML/CSS/WebGL2 interface with SVG plots and labels.
- `tests/`: analytical cantilevers, rigid-motion invariance, tangent consistency, equilibrium gradients, convergence reporting and search invariants.

## Intel graphics

CPU is the default compute device. It avoids initializing the Intel runtime just to run a device benchmark. Device selection is exposed in the Configure synthesis dialog.

The environment installs the Intel XPU build of PyTorch from its official wheel index. `--device auto` benchmarks batched tangent assembly and solves on CPU and Intel XPU, then chooses the faster device for this problem size. The result is cached for subsequent resets. Use `--device xpu` to require GPU execution or `--device cpu` for CPU execution. Explicit XPU selection fails if the GPU is unavailable or lacks float64 support. The current machine's Intel Arc B390 has been checked with nonlinear equilibria and gradient parity tests against CPU.

Beam energy, derivatives, tangent assembly and linear solves execute on the selected device. Newton uses a regularized solve and a device-local, diagonally dominant fallback if the Newton direction is not finite and descending. Line search checks the true potential. The minimum-eigenvalue diagnostic uses CPU once per equilibrium attempt, outside the Newton iteration loop, because this PyTorch XPU build does not implement that eigensolver. The 3D kernels batch all beam rotations and strains, and element tangents use vectorized autodifferentiation. GPU overhead can dominate tiny structures; GPU selection does not imply a speedup at every problem size.

The browser uses WebGL2 for geometry rendering and its own graphics device, independently of the Python compute device. Enable hardware acceleration in the browser. For XPU driver requirements, see the [official PyTorch Intel GPU guide](https://docs.pytorch.org/docs/2.14/notes/get_start_xpu.html).

Measured time, RAM, XPU allocator memory and browser heap are documented in [PERFORMANCE.md](PERFORMANCE.md). Repeat backend measurements with `uv run python -m compliant_mechanism_synthesis.diagnostics`.
