# Compliant Mechanism Synthesis

A local workbench for direct optimization of point-and-beam compliant mechanisms in **3D**, with one fixed support and two independent rigid bodies. Prescribe the motion of the **active** body; the **passive** body's position and orientation emerge from nonlinear elastic equilibrium. Optimize geometry, radii and connectivity so that the passive output follows a desired trajectory. No learned models.

```sh
uv sync --extra dev
uv run cms-view
uv run cms-view --steps 16 --port 8765
uv run pytest -q
uv run python -m compliant_mechanism_synthesis.search_benchmark --device cpu
uv run --with tensorboard tensorboard --logdir runs/
```

Open **http://127.0.0.1:8000**. The Specification page edits node coordinates/roles, beams/radii, the prescribed active pose and desired passive pose at each progress waypoint. Translation is entered in mm, rotation in degrees; node coordinates and radii are stored in SI units. The input and output each have cubic Hermite interpolation. Each fixed, active and passive body requires at least three non-collinear attachment nodes. A zero-pose rest waypoint can occur inside the input path: the analysis prepares its initial input from undeformed rest and then traces the requested path, including motion on either side of rest.

Both pages present full-width sections in a single sequence. Within each section, fields, plots and candidate cards adapt to the available width. A neutral light interface surrounds the dark WebGL workspace; settings are grouped by physical or search function, and each section keeps its own actions beside its heading. Synthesis settings appear beside the operation they control: population and diversity beside alternatives, mutation and parent selection in Evolution, step sizes beside gradient diagnostics, objective weights beside motion comparison, and FEM resolution beside nonlinear diagnostics. Each section applies only its own pending changes; edits in other sections remain available. Cycle settings sit beside the search controls. The compute section changes the device and explicitly restarts from the applied specification. Switching pages keeps pending edits without applying them.

The motion comparison section also shows real and desired **passive-center trajectories together**, with reference frames at shared progress samples and a synchronized current-pose marker. Coordinates are physical displacements from rest in mm, independent of viewer magnification. Real translation interpolates computed equilibria; orientation uses the same quaternion interpolation as playback. Click a sampled frame to inspect that progress. In 3D, drag the independent comparison view or select XY/XZ/YZ projection; per-coordinate charts remain available below. Static path geometry is cached per snapshot, view and frame density. No extra FEM solves are required.

The WebGL2 viewer shows **orange active**, **green passive** and **violet desired passive** bodies. Real and desired passive poses are synchronized at the same progress, with physical position/angular errors and a common-origin orientation inset. Trails show only the centers of the active body, passive body and passive target. Rigid reference frames remain visible. Playback interpolates between FEM states, preserves both rigid bodies exactly, and uses shortest-arc quaternion interpolation for 3D orientations; it does not compute extra equilibria. Visual magnification scales each body's translation while preserving its shape and true rotation. Buttons enable automatic rotation in the main viewer, trajectory comparison and specification preview; the first two also support manual orbit. Export JSON contains both poses, node configurations, reaction, energy and diagnostics.

## Nonlinear input-output mechanics

- Designs use `fixed`, `active`, `passive` and `free` roles. Fixed nodes are exactly clamped. Nodes on each body share an independent finite rigid-body transformation. Beam ends have no rotational releases: all joints transfer moments.
- Circular-section Euler–Bernoulli beams support axial/bending energy and 3D torsion. The corotational energy permits large motions and rotations with small local strains. Point coordinates and radii use differentiable PyTorch float64 computation on CPU or Intel XPU.
- Generalized coordinates are ordered as free-node DOFs, passive body pose, active body pose. **Only the active pose is prescribed.** For every input increment, Newton minimizes elastic energy with respect to free and passive DOFs, using a tangent-based prediction from the previous converged configuration, followed by Newton correction. Predictor correction in passive position/orientation triggers interval subdivision even when Newton converges; configurable tolerances are indicators rather than certified interpolation bounds. Set `predictor=0` to reuse the previous state directly. Each iteration recomputes energy, residual and the tangent of the deformed structure, including curvature of both rigid-body transformations.
- Failed increments are retried with smaller progress steps down to `minimum_increment`. Individual failures do not prevent the remaining designs from converging. Local stability is checked on the unknown-DOF tangent by a device-local LDL positivity test. Unstable equilibria are rejected; the tool does not trace unstable branches or simulate dynamics.
- The passive target only scores the resulting motion. Changing it reuses the mechanical path; changing the active input or continuation settings invalidates that path. Each accepted state stores progress, active/passive pose, positions/rotations, elastic energy, generalized actuator reaction, residual and Newton iteration count.
- Gradients use the implicit derivative of nonlinear equilibrium at each computed state, including dependence on the prescribed input. Detached parent equilibria bypass Newton when computing gradient proposals. This applies to smooth stable equilibrium branches; topology, step subdivision and branch changes are discrete decisions.

There are no prescribed external passive loads in this formulation. Contact forces, plasticity, shear deformation and inertia are excluded. Beam collisions are penalized geometrically in the objective; they do not constrain equilibrium. Nonlinear mechanisms can have multiple equilibria; continuation follows the locally stable branch reached from rest. Rotation-vector coordinates require care near π. Linear stiffness and load-controlled FEM functions remain independent analytical verification tools, not the synthesis model.

## Search and diagnostics

The default design has 33 nodes: three fixed, three active, three passive and twenty-four irregularly sampled free nodes, with 85 initial beams for the default seed and 519 admissible connections. The default geometry uses the search seed, has a 9 mm minimum node separation, and is reproducible across CPU/XPU. Connections use the union of each node’s four nearest admissible neighbors, plus a short-edge spanning tree to ensure connectivity. The neighbor count is configurable beside Restore example; there are no random long-range initial links. The 3D seed also samples irregular out-of-plane coordinates. Active, passive and fixed reference geometry remains fixed during synthesis; gradient descent optimizes free-node coordinates and radii. Beam presence is strictly binary and only evolution adds/removes connections; there are no continuous beam weights. Topology mutation draws at most two distinct edits per candidate by default. Each edit is applied with probability 0.6 (scaled for local variants), then chooses addition/removal with probability 0.5, independently of the number of absent/present edges. Within that operation, distance weights favor short additions and long removals. The edit budget, application probability and addition bias are configurable beside Evolution. The reference distance and exponent are configurable, with exponent zero restoring uniform probabilities. After mutation/crossover, every viable offspring receives a configurable number of gradient steps (default one) before survival selection; parents and elites remain available during that refinement. Disconnected designs are rejected before FEM.

The spatial single-segment solver shares the vectorized element and local assembly kernel with subdivided beams. Its implicit first derivative holds the inverse equilibrium tangent fixed and avoids constructing a graph for that inverse. Final stiffness derivatives remain enabled whenever the support cost needs them; complete cached paths above the support floor omit those inactive derivatives. Geometry sampling prunes absent connections before interpolation. These optimizations retain the same continuation resolution and objective components.

Equilibrium sensitivities now use an explicit first-order adjoint. Newton runs on detached primal data; CPU uses native Cholesky and XPU uses on-device LU with a physical positivity check. Translational coordinates are scaled by the configured characteristic length for the global and adjoint solves, while physical residual acceptance remains conservative. Private beam adjoints are condensed and recovered, so collision and length gradients include the internal deformation.

Exact paths keep detached factorizations on the selected compute device, bounded by `linearization_cache_mb` (default 256 MiB) and pruned with the retained population. Cache eviction preserves path records: it affects speed, not correctness. Compatible cached paths can attach their adjoint directly without Newton or refactorization; active support penalties still differentiate the explicit stiffness. Gradients of gradients through the equilibrium attachment are outside this implementation's scope.

Parent-path hints are separate from exact cache entries. They apply only to unchanged topology/discretization/input, geometry changes within 0.5 mm and present-radius changes within 5% by default. Candidate guesses must also remain within the child's own continuation predictor tolerances. Newton, stability and physical residual checks always run; ambiguous corrections are retried from the child's continuation guess. Preloading still starts from rest. These local checks do not certify global branch identity near multistability; the reuse option can be disabled beside Population. TensorBoard reports tangent assemblies, factorizations, reused systems, adjoint solves and hint fallbacks. Compute also displays factor-cache memory.

Evaluation and gradient batches group similar binary topologies and compatible cached continuation grids. A configurable union/mean-present beam ratio (default 2) limits padded element work; batch sizes are upper bounds. Scores and gradients return in the original candidate order. Completed cached paths are kept separate from uncached candidates and from paths sampled at other progress values. Compute diagnostics and TensorBoard show the useful fraction of beam slots.

The objective integrates passive position/orientation error along the nonlinear input path, with independent physical scales and weights. It penalizes material and crowded nodes, and insufficient passive support when the active body is held and free nodes relax. The effective passive stiffness is a Schur complement, with a characteristic length for comparing rotational and translational units. The support floor prevents uniformly soft designs from achieving an unloaded transfer merely by reducing all beam radii.

Two additional differentiable costs live beside the structure viewer. **Collision loss** treats sampled cubic deformed beam centerlines as capsules with each beam’s radius and optional clearance. It sums the worst sampled squared relative penetration per present beam pair across accepted states and configurable interpolated path samples. Joint exemptions apply only near shared attachment nodes; overlapping branches beyond that vicinity are penalized. A separating subgradient handles exactly intersecting axes, where squared distance alone would stall. AABB broad phase and chunked/checkpointed narrow phase bound temporary memory. This is sampled geometric collision avoidance, not a continuous-time guarantee or a contact-force simulation; collisions with rigid-body surfaces and a beam against itself are not included.

**Length loss** penalizes whole-beam lengths below/above configurable limits (default 10–50 mm), considering rest and the sampled deformation path. Internal FEM segments are never individually penalized. These bounds are preferences rather than a buckling certificate. Weights, clearance, sampling and joint allowance are adjustable live and reuse cached equilibria. Selected-design diagnostics and TensorBoard report geometry costs, colliding pair count, maximum penetration and length range.

The default population retains 32 structures and evaluates up to 16 in a tensor batch. Gradient graphs use smaller configurable batches of 4 to bound memory with the denser design. Connections absent throughout a synthesis batch are excluded from its mechanics graph: their topology mask already makes their logit gradients zero. Gradient backtracking accepts the first nonworsening step per parent. Every hybrid cycle consists of a configurable number of gradient steps (default three), followed by exactly one evolutionary generation. Evolution focuses most local variants on the better parents while retaining exploration; survival combines cost with structural similarity to preserve diversity. These parameters are configurable live.

The learning rate adapts by default to target a **90% first-attempt improvement fraction** among candidates with finite baseline costs. Failed proposals count against that fraction; unchanged costs and differences at numerical roundoff do not count as improvement. Backtracking continues to accept only nonworsening steps per design. After each population or offspring refinement, the next rate is multiplied by `exp(response × (fraction − target))`, bounded to a factor of 0.5–1.25 and the configured minimum/maximum rate. This simple feedback uses existing score evaluations. The initial/manual rate, automatic/manual mode, target fraction, response and bounds are configurable beside gradient diagnostics. A manual-rate or mode change resets the current rate; `current_learning_rate` in snapshots is separate from the configured initial rate. History and TensorBoard include the observed fraction, target and next rate. The percentage is a control target, rather than a guaranteed fraction for every finite population.

The diagnostic panel plots requested/accepted/next learning rates, first-attempt improvement fraction versus its target, acceptance by backtracking attempt, and candidate cost improvement. It also displays Newton iterations, residual/tolerance and passive support stiffness along the input path. A refinement button solves the selected structure with twice the input increments and compares passive position/orientation and integrated tracking cost without changing the search. This is evidence of path resolution, not proof of branch uniqueness. TensorBoard writes optimization and mechanics diagnostics into `runs/`.

Vectorized local beam Hessians are assembled through exact nonlinear nodal maps. In 3D, the element gradient computed by Hessian differentiation is reused for rigid-body curvature. Converged Newton members skip intermediate tangent assembly. Newton defaults to fixed-size masked batches on XPU and compacts pending designs on CPU. The synthesis Analysis settings can override this with `newton_batch_mode` (`auto`, `compact`, `masked`). Finished members remain frozen, and computation stays on the selected device. Masks remove dynamic compaction inside Newton, but adaptive continuation and loop termination still synchronize. Small passive spectra use a device-local Jacobi eigensolver on XPU to avoid native CPU fallback. Binary topology is pruned once per input path and reused across all equilibrium corrections; cached equilibrium sensitivities skip detached Newton-batch preparation. Detached path caches are bounded by retained population; viewer responses reuse these equilibria without solving again. Configuration dataclasses define CLI defaults; `uv run cms-view --help` lists them.

## Code layout

- `mechanics.py`, `elements.py`: graph contract, material, linear assembly and independent rigid-body reduction.
- `nonlinear.py`, `tangents.py`: corotational energy, nonlinear body configurations and exact element tangent assembly.
- `prescribed_motion.py`: nonlinear active-input/passive-output equilibrium continuation and implicit derivatives.
- `spectral.py`: small spectra and stability checks on CPU/XPU.
- `optimization.py`: persistent batched gradient/evolution search and cached deformation paths.
- `trajectory.py`, `resolution.py`: input/target interpolation and nonlinear path refinement.
- `server.py`, `web/`: serialized local API, specification editor, synthesis controls and WebGL viewer.

CPU is the default compute device. Auto benchmarks actual two-body nonlinear continuation after warmup; explicitly selecting Intel XPU can be slower for these small matrices and uses additional native-runtime RAM. Intel XPU requires a float64-capable device and a supported PyTorch installation. The browser uses its own graphics device independently of Python; enable browser hardware acceleration. Detailed CPU/XPU operation traces can be generated with `uv run python -m compliant_mechanism_synthesis.trace_diagnostics --device xpu`. Backend measurements and profiling commands are documented in [PERFORMANCE.md](PERFORMANCE.md).

The selected design reports maximum beam normal strain (axial extension plus endpoint extreme-fiber bending), torsional engineering shear strain, critical beam/progress, actuator force and generalized rotation-conjugate moment over the sampled path. These are diagnostics, not material failure constraints: joint concentrations, transverse shear and yielding are not modeled. In 3D the rotation-vector-conjugate moment is not a spatial torque. `passive_support_weight` and `minimum_passive_support` score the smallest passive stiffness eigenvalue with the actuator blocked and free nodes relaxed; this covers all directions, not only directions transverse to the target.

Spatial beam subdivision is integrated into nonlinear synthesis. Set **Nonlinear diagnostics → FEM resolution → Internal segments per beam** (Spanish UI: `Segmentos internos por viga`), or launch `uv run cms-view --beam-segments 4`. The default remains one segment. `condensed_mechanics.py` preserves exact fixed clamps and independent active/passive rigid ties, including rigid-map curvature. Segment kernels batch all beam interiors and condense both tangent and residual before the global solve. CPU scatters transformed local 12×12 blocks; XPU uses flattened matrix contractions, avoiding a global-sized matrix per beam. Private-node corrections are recovered within global Newton, without nested per-beam Newton loops. The continuation predictor includes interior sensitivities; caches retain detached private interiors of present beams and replay implicit gradients without Newton. Changing resolution invalidates the path cache. The viewer interpolates the actual computed mesh, preserving rigid endpoints, and diagnostics use segment strains. The global graph retains its original nodes/connections. Spatial segment kernels include torsion and exact rotation-vector rigid-map derivatives; paths and design gradients are checked against uncondensed spatial meshes. Planar kernels remain independent analytical verification tools, with no planar synthesis mode.

`subdivided.py` also contains a small prescribed-nodal validation solver. All components remain interleaved; changing memory layout is a separate experiment.

Run the reproducible two-beam nonlinear network experiment with:

```sh
uv run python -m compliant_mechanism_synthesis.subdivision_diagnostics --device cpu --batch-size 16 --segments 4
```

Results include junction coordinates, private beam meshes, convergence and timing in `runs/diagnostics/subdivision.json`. The tests compare the condensed step and complete nonlinear solution against uncondensed systems, analytic single-beam stiffness, energy derivatives, CPU/XPU, finite-difference radius sensitivities and mesh refinement. Rigid-body paths and position/radius gradients are also compared against uncondensed meshes. A separate-component layout has not been benchmarked.

For equal-resolution continuation performance and isolated memory measurements:

```sh
uv run python -m compliant_mechanism_synthesis.subdivision_benchmark --device cpu --segments 4 --steps 4 --repeats 3
```

This runs condensed, uncondensed and original single-segment models in separate processes, checks refined-path equivalence, and writes JSON and TensorBoard data in `runs/diagnostics/`. Timing excludes startup/warmup. Comparison workers have a configurable `--timeout-seconds` limit (180 by default); timeouts are reported without a speedup. The single-segment model is a coarser physical approximation and is not the denominator for the condensation speedup. See [PERFORMANCE.md](PERFORMANCE.md).

To measure independent segment kernels and local condensation as batch sizes increase:

```sh
uv run python -m compliant_mechanism_synthesis.beam_scaling
```

This checks CPU/XPU agreement and writes `runs/diagnostics/beam-scaling.json`; it does not measure global equilibrium or a complete synthesis iteration.

## Progressive analysis

New searches start with a small-displacement **linear** model and one element per beam. The rest tangent is assembled once per design batch, and all prescribed active poses share one factorization with multiple right-hand sides. Fixed nodes remain clamped and active/passive bodies retain independent rigid reductions. First-order design gradients differentiate the linear equilibrium; analytical stiffness, finite differences and small-amplitude nonlinear paths check this approximation on CPU/XPU.

The search advances once to nonlinear equilibrium continuation when the best integrated motion loss reaches `linear_motion_loss_target` (default 0.02), motion improvement stalls for `linear_stagnation_iterations` (5), or `linear_max_iterations` (20) expires. Stagnation ignores improvements below 0.1% and uses motion loss, separately from material/collision costs. Every `fidelity_check_interval` iterations (5), the best and dissimilar alternatives (2 by default) also undergo nonlinear continuation. Excess normalized passive pose discrepancy (`fidelity_pose_error_limit`, 0.1) or failed continuation advances the search. These checks are also performed before a planned transition.

At transition, the entire retained population is reevaluated, old path/factor caches are cleared and the adaptive learning rate is reset. Linear and nonlinear scores are never compared in selection. TensorBoard records motion loss, checked pose discrepancy and the transition. The viewer labels linear paths as approximate; a completed nonlinear path is required for `trajectory_validated`. The resolution comparison button checks linear versus nonlinear motion during exploration, and doubled nonlinear path increments afterwards.

Controls live under **Modelo y recorrido → Inicio lineal y transición**. Setting `staged_analysis=0` switches a current linear search immediately to nonlinear; enabling it again affects the next restart. CLI: `uv run cms-view --staged-analysis 0` starts directly with nonlinear analysis. Automatic progression currently has two levels: linear and nonlinear, both with one element per beam. More spatial segments can be configured after transition, or from startup with staged analysis disabled. Spatial refinement after the nonlinear transition is controlled independently, as described below; geometric nonlinearity and spatial resolution remain separate choices.

### Adaptive spatial resolution

Nonlinear searches now enable `adaptive_beam_resolution` by default. Starting from the current resolution, checks compare it with twice as many segments (capped by `mesh_max_segments`, default 4). A check waits at least `mesh_min_iterations` (5) iterations at the current level, and respects `mesh_check_interval` (10). It runs when the best motion loss is below `mesh_motion_loss_target` (0.05), total-score improvement has stalled for `mesh_stagnation_iterations` (5), or `mesh_max_iterations` (20) iterations have elapsed at that level. Candidate count uses `fidelity_check_candidates`: the best and dissimilar retained alternatives are solved together in a detached mechanics batch.

The checker compares passive-center position and geodesic orientation at common prescribed input poses across the full completed paths. Extra adaptive continuation samples are excluded to separate spatial error from input sampling. Maximum tolerances are in SI units: `mesh_position_tolerance` (0.1 mm) and `mesh_orientation_tolerance` (0.002 rad). These tolerances do not depend on target position/orientation weights. If a completed finer path exceeds either tolerance, or succeeds where the coarse path failed, the entire population is reevaluated at the finer resolution. All old path and factor caches are discarded; already computed finer equilibria are reused, and the adaptive learning rate resets. Resolution increases are monotonic unless changed manually.

Accurate coarse meshes are retained. An incomplete finer solve is reported and retried at a later eligible check; failure alone does not establish a spatial error or certify the coarse design. The segment cap is a computational budget, not proof of mesh convergence. Checks sample alternatives and input poses rather than bounding the error of every design or the entire continuous path. They do not certify beam stresses, internal shape or contact accuracy. A nonlinear completed path (`trajectory_validated`) also does not imply spatial convergence.

Controls and the last check's positional/angular differences, failures, samples and decision appear under **Modelo y recorrido → Refinamiento espacial**. TensorBoard records them under `mesh/`, including check time and actual segment increases. Set `adaptive_beam_resolution=0` for a fixed manual mesh. Changing FEM settings restarts the spatial checking schedule. Benchmarks default to fixed resolution independently of whether their initial linear stage is enabled; use `--adaptive-beam-resolution 1` to include checks and automatic refinement in complete-search timings.

The movement comparison shows all six passive pose coordinates simultaneously in a responsive grid with a shared vertical range in weighted normalized units, with synchronized playback markers. The input-resolution comparison also displays all six coordinates and their differences. Default initial gradient rate is 0.1; default mutation intensity is 0.2. Both remain configurable beside their respective synthesis controls.

Coordinate charts divide each translation/rotation-vector component by its position/orientation tolerance and by `sqrt(3)`. All six share the same normalized vertical range, including the resolution-comparison grids. Equal vertical discrepancies correspond to equal positional loss contributions. The orientation interpretation is local: the actual loss uses the geodesic relative rotation, so differences of rotation-vector components are not an exact angular loss decomposition for finite rotations. Physical mm/degree values remain in state diagnostics and the joint trajectory view.

Tracking has only two parameters: `position_tolerance` (meters internally, mm in the UI) and `orientation_tolerance` (radians internally, degrees in the UI). The loss is the sum of mean squared position and relative-rotation errors divided by their respective tolerances. Separate tracking weights and scales were removed from the API and CLI. Defaults are 10 mm and 0.1 rad (about 5.73°); compared with the previous equally weighted average, their summed tracking contribution doubles. Other cost weights still express separate physical tradeoffs. These objective tolerances are distinct from mechanics predictor tolerances and spatial-refinement tolerances, which control solver sampling and accuracy.

The loss-history section shows weighted position, orientation, passive support, material, collision, length and node-spacing contributions plus their total, on a shared vertical scale. Samples describe the best retained candidate after each optimization iteration or configuration reevaluation; the best candidate can change. Dashed markers identify linear/nonlinear and mesh transitions or objective-setting changes. At most 300 samples are kept, detached component caches are pruned with the population, and recording reuses objective values without extra mechanics solves. TensorBoard stores these under `loss_components/`.
